# PPTX 페이지 단위 텍스트 수정 — 0.12.0

## 사용 흐름

1. PPTX 편집기에서 플러그인을 열고 로컬 LLM 서비스에 연결한다.
2. 작업에서 **페이지 텍스트 수정**을 선택한다. 수정할 페이지 번호를 입력하거나 비워 두어 현재 슬라이드를 사용한다.
3. **페이지 읽기**로 제목·본문 등 수정 가능한 텍스트와 제외 개체 수를 확인한다. 개체 테두리를 하나씩 선택할 필요가 없다.
   기본값은 숫자 보존이다. 예산 변경처럼 숫자를 실제로 바꾸려면 **숫자 변경 허용**을 선택하고 다시 읽는다. 옵션 변경은 이전 캡처·수정안을 폐기한다.
4. 자연어로 요청한다. 예: ‘이 페이지 전체를 임원 보고용으로 간결하게 다듬고 수치와 고유명사는 유지해 주세요.’
5. **페이지 수정안 요청** 후 변경 전·후를 확인한다. 이 단계에서는 문서를 쓰지 않는다.
6. **페이지에 일괄 적용**을 누른다. 문서의 문맥·줄 넘침을 확인하고 편집기에서 저장한다. 다음 수정 요청 전 페이지를 다시 읽는다.

기존의 단일 텍스트 상자 수정과 별개다. 한 페이지의 여러 텍스트 상자·문단·서식 구간을 한 요청으로 전달한다. 로컬 모델의 작은 컨텍스트·토큰 한도 때문에 긴 페이지는 요청/응답이 거부될 수 있다. 모델이 사실·수치를 보존했다는 자동 인증은 제공하지 않는다.

## 적용과 복구

모델은 알려진 모든 텍스트 구간에 대한 수정안을 JSON으로 반환하며 원문 유지 구간도 포함한다. 모르는 대상·중복·누락·추가 명령·빈 문자열·줄바꿈·상한 초과는 거부한다. OpenAI 호환 경로는 JSON schema를 함께 보내므로 해당 서버의 지원이 필요하다. Anthropic 경로는 JSON 본문을 받아 같은 검증을 수행한다. 임의 코드·도구 호출은 실행하지 않는다.

숫자 변경을 허용하지 않은 경우, 원문·수정안의 숫자 토큰과 등장 횟수가 다르면 서버와 편집기 양쪽에서 차단한다. 이는 숫자 누락/변경을 막는 보수적 검사이며 같은 숫자를 잘못된 항목에 연결하거나 단위·고유명사·사실을 바꾸는 오류까지 잡는 의미 검증은 아니다. 숫자 표현을 다른 방식으로 고치려는 경우도 명시 허용이 필요할 수 있다.

적용 직전에 페이지 번호·개체 목록·문단/구간 구조·원문을 다시 읽어 캡처와 비교한다. 하나라도 달라지면 쓰기 전에 중단한다. 사용자가 다른 슬라이드로 이동했더라도 캡처한 원래 페이지에 적용한다.

기존 run 객체를 재사용하고 서식 구간 앞뒤 공백을 보존한다. 뒤쪽 쓰기가 실패하면 해당 구간과 앞서 변경한 모든 구간을 역순으로 복구하고 원문을 확인한다. 복구 여부를 확인하지 못하면 추가 편집·저장 전 확인/실행 취소/사본 복구를 안내한다. 이는 자체 복구 절차이며 실제 엔진의 원자적 트랜잭션을 보장하지 않는다. 새 기능의 단일 undo/redo와 저장·재열기는 별도 Desktop QA 대상이다.

## 범위

- 한 번에 한 슬라이드, 최대 60개의 비어 있지 않은 일반 텍스트 구간. 문단/구간 정보가 포함된 요청은 12,000자 이하, 수정안 전체도 12,000자 이하.
- 여러 문단·서식의 텍스트를 지원하지만 문단·서식 구간을 추가/삭제/병합하거나 새 도형을 만들지 않는다. 같은 개체·문단 정보도 모델에 전달한다.
- 이미지·표·그룹·노트·마스터·일반 run 이외의 필드를 가진 개체 등은 제외한다. 내부 줄바꿈이 들어 있는 run도 지원하지 않는다. 제외 개체 수를 먼저 확인한다.
- 위치·글꼴·도형 크기·슬라이드 배치를 변경하지 않는다. 텍스트가 길어지면 넘칠 수 있으며 자동 맞춤은 없다.
- PDF 페이지 편집은 미구현이다. Marker는 읽기/분석용이며 원본 PDF/PPTX의 편집 엔진으로 사용하지 않는다.

## 확인한 것과 남은 것

실제 Qwen2.5 1.5B 로컬 추론으로 모의 페이지의 제목·본문 수정안, 사전 검토, 일괄 적용, 다른 페이지 유지, 재읽기를 헤드리스 브라우저에서 확인했다. 페이지 SDK 명령은 모의 API에서 여러 문단/서식·충돌·실패 복구를 검증했다. **새 페이지 기능의 실제 ONLYOFFICE 동작·서식 렌더링·저장은 별도 VM/전용 PC에서 검증 전**이다. 기존 단일 개체 실증을 페이지 전체 검증으로 확대 표기하지 않는다.

실추론 재시도에서 모델이 예산 숫자를 누락한 사례를 관찰하여 위 숫자 검사를 추가했다. 최종 브라우저 기능 시험은 숫자 없는 합성 문장으로 수행했고, 숫자 변경 차단/명시 허용은 계약·두 프로토콜 HTTP·편집기 명령 테스트에서 별도로 확인했다. 한 번의 수정 성공을 모델의 사실 보존 신뢰도로 확대 해석하지 않는다.
