# PDF 분석 파일 가져오기, 실험적

0.15.0은 기존 Marker/pdfplumber CLI의 추출 JSON을 PDF 패널에 연결한다. 자동 추출 엔진을 앱에서 실행하는 기능이나 PDF 편집 기능은 아니다. 실제 Desktop PDF 파일 선택·패널 인수는 미완료다.

## 사용

1. 기존 [Marker 비교 실험](marker-evaluation.md)의 추출 CLI로 분석 JSON을 준비한다. Marker 2.0.0, useLlm=false, OCR 켬/끔이 명시된 schemaVersion 1 패킷 또는 pdfplumber 패킷을 지원한다.
2. PDF 패널에서 질문/요약과 ‘첨부 PDF 분석 파일’ 범위를 선택한다. 로컬 서비스 연결 후 분석한 원본 PDF와 JSON을 첨부한다.
3. 시작·끝 페이지를 지정하고 ‘첨부 분석 페이지 읽기’를 누른다. 비우면 첫·마지막 추출 페이지다. 페이지별 원문과 추출 품질을 원본 PDF와 대조한다.
4. 질문 또는 요약을 요청한다. 답변의 `[page N]` 표기와 읽은 페이지를 비교하고 필요하면 기존 보고서를 내려받는다.

PDF 최대 20MiB, JSON 최대 2MiB, 패킷 최대 200페이지, 읽은 페이지 출처를 포함해 12,000자다. 파일은 브라우저에서 읽고 해시를 계산하며 원본 PDF/JSON을 HTTP로 업로드하지 않는다. 기존 인증된 질의 API에는 선택한 페이지 텍스트와 요청만 보낸다. SHA-256은 보고서 출처에 기록한다.

## 실패와 한계

PDF 파일 헤더·SHA-256과 JSON의 documentSha256 일치를 확인한다. 불일치·잘못된 UTF-8/JSON·지원하지 않는 메타데이터·중복/누락 페이지·잘못된 범위·전체 빈 선택·NUL·길이 초과·해시 기능 부재는 중단한다. 부분 결과를 잘라서 보내지 않는다. 파일/범위를 바꾸면 이전 읽기와 현재 답변을 무효화하며 기록은 유지한다.

해시 일치는 첨부한 두 파일의 연결만 확인한다. JSON 텍스트의 진위·추출 정확성이나 현재 편집기에 열린 PDF와 같은 파일인지는 보장하지 않는다. 출처 번호가 존재해도 답변의 사실성은 보장하지 않는다. 보고서는 원문 사본을 자동 추가하지 않지만 질문·답변에 원문이 포함될 수 있다.

기존 CLI 결과를 읽는 UI 연결까지 구현했다. 앱 내 자동 Marker 실행/모델 설치·원본 페이지 위치 대조·PDF 수정/저장·실제 Desktop 패널 검증·사내 LLM 인수는 별도 미완료다. [QA](../qa/2026-10-22-marker-packet.md), [전체 완료 기준](../06-completion.md).
