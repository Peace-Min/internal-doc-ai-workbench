## 2026-10-18: 요구와 설계 후보 정리

### 사용자 확정 사항

- 클라우디움과 사내 LLM은 이미 폐쇄망에 구축되어 있다.
- 클라우디움 문서를 자체 뷰어·에디터에서 열고 편집하면서 AI를 활용한다.
- 유료 상용 에디션에 의존하지 않는 공개 소스 구성을 지향한다.
- 개발 소스 공개와 라이선스 고지를 유지할 계획이다.
- 기획 → 개발 → QA → Wiki 워크플로우로 진행한다.
- 다른 PC·세션에서 이어갈 수 있게 공개 GitHub에 기록한다.

### 설계 후보 (검증 전)

- ONLYOFFICE Community를 주 편집기로, 자체 플러그인을 AI UI로 검토한다.
- Marker는 편집기가 아니라 선택적 분석 서비스로 둔다.
- PPTX는 원본 개체 정보, PDF는 분석 블록과 위치 정보를 활용한다.
- AI가 제안한 수정은 미리보기·대상 검증 후 편집 엔진이 반영한다.
- 위 기능은 내부망 서비스만 호출하도록 구성한다.

### 미확정

웹/데스크톱 운영 형태, 엔진 고정 버전, 플러그인 API 범위, 클라우디움 API, LLM 규격, PDF 편집 수준, Marker 모델 적합성, 자체 프로젝트 라이선스.

## 2026-10-18: PC 설치형 PoC 0.1.0

- 사용자 결정: PC 설치형 데스크톱 앱 우선. 이전 웹 서버형 가정은 대체한다.
- ONLYOFFICE Desktop Editors 10.0.0과 그 SDK 커밋을 조사 기준으로 고정한다.
- 별도 Electron 셸보다 먼저 Desktop Editors 플러그인과 로컬 서비스로 실제 개체 조작 가능성을 검증한다. 완성된 자체 데스크톱 앱은 아직 아니다.
- 원래 개체 ID와 텍스트 비교로 대상 변경을 방지한다. 텍스트 상자 전체·한 문단·한 run만 첫 적용 범위로 한다.
- 외부 패키지 없는 Node 22.14+ 로컬 서비스, 기본 모의 AI, 명시 설정 시 OpenAI 호환 내부 LLM 어댑터를 구현한다.
- pairing token은 private/runtime.json에 로컬 생성하고 플러그인 메모리에서만 사용한다. 실제 Origin 확인 전 무분별한 CORS 허용은 하지 않는다.
- Marker와 클라우디움은 아직 연결하지 않는다. 엔진 실증을 먼저 수행한다.
- 프로젝트 자체 코드는 AGPL-3.0-only로 공개한다. 포함 SDK의 추가 고지는 별도로 보존한다.
- 자동 테스트 11개와 브라우저 모의 적용·충돌 흐름을 확인했다. 실제 Desktop Editors가 없어 설치·개체 API·undo·저장·서식 보존은 미검증이다.

### 대화 중 설명의 적용 한계

‘오프라인 운영 가능’은 설계 가능성을 의미하며 실제 차단 환경에서 검증되지 않았다. ‘플러그인으로 수정 가능’은 노출된 API 범위에 한정되며 모든 PPTX/PDF 개체 조작을 보장하지 않는다. ‘공개 소스 사용’은 모든 모델의 무제한 기업 사용을 의미하지 않는다.
