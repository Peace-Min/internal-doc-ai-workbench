# 결정 이력

## 2026-10-21: PDF 선택 텍스트 분석 후보 0.14.0

- 기존 Desktop 앱/플러그인을 재사용하고 PDF 변형은 GetSelectedText와 질문/요약만 허용한다. 페이지 번호를 추정하거나 PDF 본문 수정에 연결하지 않는다. 기존 기록·원문 대조·보고서에 PDF 선택 범위를 명시한다.
- 자동 101개와 브라우저 모의 SDK 흐름, VM 100개 통과/호스트 전용 1개 제외. 동일 설치 엔진에서 실제 PDF 첫 화면도 확인했다. 모의 API 검증과 실제 PDF 열람을 실제 선택/패널 인수로 합치지 않으며 실험적 표기를 유지한다.
- 원래 최종 목표인 PDF 편집·Marker UI·사내 저장소/LLM 인수는 그대로 남긴다. 이 작업을 이유로 완료 범위를 축소하지 않는다.

## 2026-10-21: 오프라인 사용자 설치와 완료 기준 0.13.0

- 별도 설치 프레임워크 대신 Windows PowerShell/ZIP으로 사용자 계정 설치기를 제공한다. 편집기/Node 고정 해시를 검사하고 기존 앱/설정을 덮어쓰지 않으며 플러그인은 백업한다. 인터넷 다운로드·관리자 상승·자동 앱 종료/기동은 하지 않는다.
- 인터넷 차단 VM의 새 앱 설치와 PATH 없는 점검/인증 HTTP를 실제 검증했다. VC++ 런타임은 사전 설치였으며 완전한 PC 초기 설치/사내 전체 흐름으로 확대하지 않는다. health는 배포 버전에서 읽어 릴리스별 상수 불일치를 방지한다.
- UIA 호출 성공만으로 실제 탭 변경을 확정하지 않았다. 실제 입력의 no_interactive_desktop과 VM LLM 설치·실행 명령의 blocked by policy를 기록하고 우회하지 않는다. 기존 요구사항 전체의 완료 조건/외부 전제를 docs/06-completion.md에 모았다.

- 사용자 요청에 따라 호스트 화면을 제어하지 않고 기존 Sandbox 내부에서 Microsoft winapp CLI 0.7.1을 실행한다. 요청별 공유 파일과 wsb exec를 사용하며 호스트 UI 대체/자동 연결은 하지 않는다.

- 일반 게스트 컨트롤 수정 성공, 실제 편집기 로드 성공, 아직 미실행인 플러그인 수정/저장 QA를 구분한다. 호스트 클라이언트 최소화 지원은 보장하지 않는다. 앱 버전은 0.12.1 유지. 절차/QA는 background-vm 문서를 따른다.

## 2026-10-18: 요구와 설계 후보 정리

### 사용자 확정 사항

- 클라우디움과 사내 LLM은 이미 폐쇄망에 구축되어 있다.
- 클라우디움 문서를 자체 뷰어·에디터에서 열고 편집하면서 AI를 활용한다.
- 유료 상용 에디션에 의존하지 않는 공개 소스 구성을 지향한다.
- 개발 소스 공개와 라이선스 고지를 유지할 계획이다.
- 기획 → 개발 → QA → Wiki 워크플로우로 진행한다.
- 다른 PC·세션에서 이어갈 수 있게 공개 GitHub에 기록한다.

### 설계 후보 (검증 전)

- ONLYOFFICE Community를 주 편집기로, 자체 플러그인을 AI UI로 검토한다.
- Marker는 편집기가 아니라 선택적 분석 서비스로 둔다.
- PPTX는 원본 개체 정보, PDF는 분석 블록과 위치 정보를 활용한다.
- AI가 제안한 수정은 미리보기·대상 검증 후 편집 엔진이 반영한다.
- 위 기능은 내부망 서비스만 호출하도록 구성한다.

### 미확정

웹/데스크톱 운영 형태, 엔진 고정 버전, 플러그인 API 범위, 클라우디움 API, LLM 규격, PDF 편집 수준, Marker 모델 적합성, 자체 프로젝트 라이선스.
