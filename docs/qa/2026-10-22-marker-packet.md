# PDF 분석 패킷 UI QA, 2026-10-22

대상: 0.15.0. 기존 저장소 합성 3페이지 PDF와 Marker 2.0.0 OCR/pdfplumber 결과만 사용했다. 이번 작업에서 Marker 추출/모델 추론을 새로 실행하지 않았다. 사내 문서·주소·인증정보를 사용하지 않았다.

## 자동 및 배포 검증

호스트 Node 전체 107개 통과, 실패 0개. 동봉 Node v24.22.0의 PATH를 비운 공백 포함 배포 경로에서 107개 통과, 실패 0개. 패키징 검사로 새 두 분석 스크립트와 HTML 참조, 플러그인/앱 버전 일치를 확인했다.

실제 fixture SHA-256 baa6cd307b827ce27318f0ea42b36aa58c1cc4c720a11c451a43460bf8aafd6f를 확인했다. Marker/pdfplumber 지원·페이지 선택/정렬·중복/누락/범위 오류·12,000자 초과·파일 누락/크기 변경·20MiB/2MiB 초과·해시 불일치·비정상 UTF-8/JSON·지원하지 않는 Marker 버전/LLM 보정·해시 API 부재·빈 선택의 거부를 시험했다.

패널 테스트는 실제 localhost 인증 HTTP를 사용했다. 3페이지만 전송하고 원본 PDF/JSON/해시를 API 요청에 추가하지 않음, SDK 호출 없음, 파일/범위 변경 후 다시 읽기, SHA-256 보고서와 페이지 출처·원문 사본 미추가, 알려진/미확인 페이지 인용 구분을 확인했다. 출처 번호 존재는 사실성 검증이 아니다.

## 헤드리스 Chrome

Playwright CLI로 실제 파일 선택 → 원본 해시 검증 → 3페이지 읽기 → mock 질의 → 원문 대조 → 보고서 다운로드를 통과했다. 1페이지로 범위 변경 시 이전 대상 무효화와 3페이지 제외를 확인했다. 다른 PDF 첨부 시 해시 불일치로 전송이 차단됐다. 제안 요청 필드는 operation/text/instruction뿐이고 SDK/쓰기 호출은 0회였다. 전체 화면을 캡처해 파일 입력·범위·원문·답변·기록·대조 영역을 확인했다.

PDF SDK는 모의 객체이고 AI는 mock이다. 실제 Desktop PDF 패널 및 실제 모델의 답변 정확성 QA를 의미하지 않는다. 호스트 화면 입력은 사용하지 않았다.

## 차단 VM

기존 VM은 종료되어 목록이 비어 있었다. 기존 반입 폴더의 과거 bootstrap/node-tests 보고서를 별도 보존하고 최신 소스·고정 Node·편집기 ZIP 해시를 검증해 새 4GB Sandbox를 화면 연결 없이 준비했다. 네트워크/클립보드 등 기존 차단 설정을 유지했다. Node v24.22.0, 플러그인 0.15.0 설치와 107개 중 106개 통과·호스트 전용 1개 제외·실패 0개를 확인했다. 새 VM에서 실제 편집기는 시작하지 않았고 actualAppLaunched/actualAppQATested=false다. 이전 VM의 설치 경로·프로세스는 현재 사용할 수 없다.

## 새 VM 제어 준비 보완

고정 WinApp 0.7.1과 VC++ 14.51.36247.0 설치를 게스트에 복원했다. 서명/해시 확인, VC 설치 코드 0 및 재시작 불필요를 확인했다. Prepare-BackgroundGuest.ps1이 과거 성공 JSON을 남기는 문제를 수정했다. 시작 즉시 ok=false/stage=preparing과 UTC startedAt를 기록하며 예외 시 실패/예외 형식만 남긴다. 고의 해시 불일치의 VM 시험으로 stale-success → failed/ok=false 전환과 코드 1을 확인했고, 원본 스크립트의 정상 재준비는 prepared/ok=true·코드 0이었다.

입력 공유 폴더에 추가한 시험 파일이 게스트에 즉시 보이지 않아 처음 두 실행은 파일 부재로 실패했다. 지정된 결과 공유 폴더에 시험 스크립트를 복사한 뒤 검증했다. 실패 주입은 별도 결과 파일에만 기록했고 실행 바이너리/입력 해시는 변경하지 않았다.

이후 ExistingLogin의 실제 편집기 시작은 0x80070520, 지정한 로그온 세션 없음으로 실행되지 않았다. System 준비 성공은 사용자 로그인/실제 UI 준비 완료를 뜻하지 않는다. 새로운 로그인이나 호스트 화면 연결로 우회하지 않았고 actualAppLaunched/actualAppQATested=false를 유지한다. 기존 VM의 no_interactive_desktop 입력 실패와도 구분한다.
