# 페이지 단위 로컬 LLM 텍스트 수정 QA — 0.12.0

## 기획 → 개발

사용자는 개체 하나씩 수정하는 수준보다 페이지 전체를 대상으로 로컬 LLM 수정 작업을 수행해야 의미가 있다고 지적했다. 한 슬라이드의 여러 텍스트 상자·문단·run을 수집하고 자연어 요청·구조화 수정안·변경 전후 검토·명시적 일괄 적용 흐름을 구현했다. 기존 선택 개체 수정/읽기 전용 분석은 유지한다.

페이지 명령은 고정 SDK에서 조사한 GetAllSlides/GetAllDrawings/GetInternalId/GetContent/문단/run API를 사용한다. 기존 run을 유지하며 문단 그룹과 구간 앞뒤 공백을 보존한다. 이미지·표·그룹 등은 제외 수로 안내한다. 페이지 구조·원문 전체를 쓰기 전 다시 검사하고 실패 시 앞선 변경을 포함하여 복구한다.

## 검증 결과

- Node 자동 테스트 **89개 통과**.
- 페이지 캡처: 두 개체·여러 문단·여러 서식 구간, 이미지 제외, 개체를 선택하지 않고 페이지 번호로 읽기.
- 페이지 적용: 원래 페이지 대상 유지, 다른 페이지 불변, 기존 서식 속성/앞뒤 공백 유지(모의 API).
- 충돌/응답 검증: 변경 없는 계획 구간의 직접 수정도 차단. 개체 추가/삭제, 누락·중복·모르는 ID·여러 줄·빈/과대한 수정안과 원문 상한 초과 차단.
- 실패 주입: 뒤쪽 부분 쓰기 실패 시 앞선 변경까지 모두 복구. 일부 복구 실패 시 실패 구간을 보고하고 다른 구간 복구는 계속 수행.
- HTTP: OpenAI/Anthropic 양쪽에서 페이지 전체 전달·완전한 계획 반환·불량 계획 502 확인. 기존 인증·CORS·출력 제한 회귀 검사 통과.
- UI: 요청 단계 쓰기 없음, 전후 비교, 적용 버튼을 누른 후에만 page_apply 호출, 페이지 변경 시 계획 폐기, 읽기 전용 보고서에 수정안을 혼입하지 않음.
- 실제 로컬 모델: llama.cpp b8201 + Qwen2.5 1.5B Q4_K_M, CPU 2스레드. 헤드리스 브라우저에서 제목·본문 2구간을 한 요청으로 수정하고 검토·모의 편집 적용·재읽기·다른 페이지 유지 확인. 재시도 중 예산 숫자 누락을 관찰하여 숫자 보존 검사와 명시 허용 옵션을 추가했다. 최종 브라우저 시험은 숫자 없는 합성 문장으로 수행했다. 숫자 검사·허용은 계약/편집기 및 양쪽 프로토콜 HTTP 시험에서 확인했다. 응답 가로채기/합성 대체 없음. 재현: assets/page-edit-browser-flow.js.
- plugin/source/Windows ZIP과 체크섬 생성. Node/Python/모델·추론 실행기 미포함.

실제 Desktop Editors UI·페이지 undo/redo·실제 PPTX 저장·재열기·서식 렌더링·줄 넘침은 미실행이다. 사용자 PC 직접 제어 금지와 별도 테스트 PC 제약을 유지한다. 실제 엔진의 원자성 보장이나 전체 레이아웃 편집으로 표기하지 않는다. PDF 페이지 수정도 범위 밖이다.
