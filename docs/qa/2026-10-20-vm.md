# Windows VM 준비 QA — 2026-10-20

## 요구와 구현

현재 기능 커밋 d8210a2를 먼저 원격 main과 동기화한 뒤 Windows 검증 환경 준비를 진행했다. 사용자 선택은 Windows 우선. 호스트 UI 점유 금지에 따라 Windows Sandbox의 백그라운드 CLI 실행·게스트 준비 스크립트를 추가했다. 앱 버전은 0.12.0을 유지한다.

호스트는 Windows 11 Pro 빌드 26200, RAM 약 16GB, hypervisor 활성 상태다. Sandbox 기능은 초기 비활성이었고 관리자 기능 활성화 결과 `ok:true`, `state:Enabled`, `restartNeeded:true`, `automaticRestart:false`를 확인했다. 재부팅은 실행하지 않았다.

## 검증 결과

- 전체 Node 자동 테스트 92개 통과. VM 설정의 XML 경로 escaping·입출력 분리·네트워크/클립보드 차단, 잘못된 배포물 해시의 반입 전 거부, 호스트에서 게스트 스크립트 실행 거부를 포함한다.
- 세 PowerShell 스크립트 AST 구문 분석 통과.
- 실제 생성 WSB의 XML 파싱 통과. 실행기를 호출해 재부팅 필요 검사에서 VM 시작 전에 거부되는 것을 확인했다.
- 고정 Desktop ZIP·Node 실행 파일·LICENSE 해시 검증 후 실제 반입 묶음 생성 완료. 편집기 ZIP SHA-256: `54979d04f1cdca56deb0c62e0356355a45f392cdb54f04f6b7e436b1f44c3605`.
- Node 24.22.0 x64 ZIP SHA-256: `f9683a19877e12a9b167305c8db71040d812876359de21f0d2e97c3f321f80c3`. 실행 파일과 고지도 versions.json 값으로 확인했다.
- 합성 PPTX만 포함. 사내 문서·인증 설정·모델은 반입하지 않았다.

## 미검증과 다음 단계

호스트 재부팅 대기다. 실제 wsb CLI 시작/응답 형식, 게스트 압축 해제·플러그인 설치·게스트 테스트는 아직 실행하지 않았다. 실제 앱 UI·페이지 편집·undo/저장·렌더링 및 VM 내부 LLM 연결도 미검증이다. Sandbox는 종료 시 초기화되며 결과 폴더의 보고서만 호스트에 남는다.

[실행·재개 절차](../wiki/windows-vm-qa.md)를 따라 재부팅 후 VM을 시작하고 게스트 보고서를 확인한다. 사용자 호스트 앱은 직접 제어하지 않는다.
