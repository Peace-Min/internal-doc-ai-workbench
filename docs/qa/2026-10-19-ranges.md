# 슬라이드 구간별 읽기 QA

- 실행일: 2026-10-19 (Asia/Seoul)
- 대상: PoC 0.7.0, 시작·끝 슬라이드·범위 표시·초기화
- 환경: Windows, 개발 Node 24.15.0, 배포 Node 24.22.0, 헤드리스 Chromium
- 합성 자료·응답만 사용. 실제 사내 문서·게이트웨이·Desktop UI 미사용

## 자동 테스트

전체 65개 통과, 실패·건너뜀 0개. 기존 60개에 5개 테스트를 추가했다.

1. 300장 문서의 250장만 읽고 원래 출처 250 및 전체 300을 유지. 선택한 장의 개체 API만 호출. 머리말 포함 12,000자 경계·1자 초과, 끝만 지정·시작만 지정 시 기본값 확인.
2. 0·음수·소수·문자열·null·NaN·Infinity·역전·문서 밖 번호는 실제 개체 탐색 전에 거부하고 부분 텍스트 없음.
3. UI 파서는 빈 경계·공백 제거·정상 정수를 허용하고 지수·소수·경로·안전 정수 초과 등을 거부.
4. 범위 입력을 편집기 명령에 숫자로 전달, 입력 변경 시 답변·캡처 초기화. 잘못된 입력은 편집기 명령 전 거부.
5. 모델 응답 대기 중 두 범위 입력 잠금 및 완료 후 해제.

기존 문서 전체 읽기, 제외·빈 개체 집계, 오류 시 부분 전송 거부, 선택 텍스트 편집·충돌·복구 테스트는 유지했다.

## 헤드리스 브라우저

두 합성 슬라이드의 총 텍스트를 12,000자 이상으로 만든 뒤 전체 읽기 거부를 확인했다. 1~1, 2~2 범위를 각각 읽고 질문·요약 요청을 실행했다. 범위 머리말과 원래 슬라이드 출처를 확인했고, 요청 본문에 선택하지 않은 슬라이드의 자료가 없음을 검사했다.

범위를 바꾸면 기존 답변과 전송 대상이 사라지고, 새 캡처 전에는 요청할 수 없었다. 문서가 두 장인데 끝 3을 지정하면 거부했으며 추가 모델 요청은 발생하지 않았다. 문서 적용 버튼은 표시되지 않았다. 브라우저 오류 로그 0개, [합성 화면](assets/range-summary.png)의 범위·출처·상한 표시 확인 후 브라우저와 임시 서버를 종료했다.

답변은 API 가로채기로 제공한 합성 응답이다. 실제 요약 품질이나 모델의 범위 준수 확인이 아니다. [CLI 재현 함수](assets/range-browser-flow.js)는 mock 데모 연결을 완료한 상태를 전제로 한다. output/playwright 폴더를 준비하고 아래를 실행한다.

```sh
npx --yes --package @playwright/cli playwright-cli -s=range-qa run-code --filename docs/qa/assets/range-browser-flow.js
```

## 배포 및 한계

런타임 포함 Windows ZIP을 새 폴더에 풀어 시스템 PATH 없이 실행기 사전 점검과 동봉 Node 24.22.0의 전체 65개 테스트를 통과했다. 인터넷 차단 신규 PC 설치와 실제 Desktop 검증은 아니다.

자동 분할·범위 추천·전체 통합 답변·기록 저장·단일 초대형 슬라이드 분할은 미구현이다. 문서 순서가 바뀌면 다시 읽어야 한다. 실제 편집기·사내 LLM 품질과 연결은 별도 환경 준비 후 확인한다.
