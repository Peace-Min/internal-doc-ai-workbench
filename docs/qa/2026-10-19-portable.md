# 실행·배포 묶음 QA

- 실행일: 2026-10-19 (Asia/Seoul)
- 대상: PoC 0.4.0, Windows 실행기·설정 점검·서비스 시작·패키징
- 환경: Windows x64, 개발 Node 24.15.0, 배포 Node 24.22.0
- 입력: 합성 문장·연결 코드·모의 LLM. 사내 데이터·게이트웨이 미사용

## 자동 검증

새 실행기 테스트 4개:

1. 다른 현재 폴더에서 프로젝트 .env를 읽어 사전 점검. 네트워크 요청·연결 코드 출력·runtime.json 생성 없음.
2. 잘못된 포트·모드·설정 파일 및 미지원 인자 거부. 설정 원문 비노출.
3. 실행기로 서비스를 시작해 실제 loopback HTTP의 mock 수정안 수신. 다른 코드의 중복 시작은 실패하고 원래 runtime.json과 활성 서비스 인증 유지.
4. runtime.json 쓰기 실패 시 새 서버가 포트를 반환하여 같은 포트 재사용 가능.

새 패키징 테스트 2개:

1. 배포물에 실행기·플러그인·소스·LICENSE 포함, 로컬 .env/private/node_modules 제외, 배포물 SHA-256 일치, Windows 실행기 CRLF 및 플러그인 버전 일치.
2. 해시가 다른 런타임·미지원 빌드 인자는 배포 전 거부.

전체 48개 테스트 통과, 실패·건너뜀 0개. 실행기 테스트는 자식 프로세스 종료까지 정리한다. Windows에서 임시 폴더 삭제 전에 실행 프로세스를 먼저 종료하도록 검증 절차를 보완했다.

## 배포물 검증

공식 latest-v24.x SHA-256 목록에서 24.22.0 Windows x64를 확인하고 고정 버전 URL로 원본 ZIP을 받았다. 공식 목록과 archiveSha256 일치 확인 후 압축 해제했으며 node.exe·LICENSE의 고정 해시를 versions.json에 기록했다. 다운로드는 온라인 준비 단계에서만 수행했다.

런타임 포함 Windows ZIP을 빌드한 뒤 공백이 포함된 별도 작업 폴더에 .NET ZIP API로 압축 해제했다. 해당 명령 환경의 PATH를 비우고 Start-Workbench.cmd --check를 실행해 성공했다. 동봉 runtime/node.exe가 24.22.0임을 확인하고 해당 실행 파일로 배포물의 전체 48개 테스트를 통과했다. 이 검사는 시스템에 설치된 Node를 사용하지 않는다.

초기 후보 Node 22.14.0 포함판에서도 실행기 점검과 당시 46개 테스트 통과를 확인했다. 최종 배포물은 온라인 준비 시 확인한 Node 24 LTS 계열의 고정 버전 24.22.0을 포함한다.

## 한계

PATH 제거와 새 폴더 실행은 인터넷 차단 상태의 깨끗한 Windows 신규 설치를 대신하지 않는다. 운영체제·보안 정책·SmartScreen·편집기 수동 설치·폰트·모델·실제 사내 통신은 이번에 검증하지 않았다. 브라우저와 Desktop Editors는 열거나 조작하지 않았다. 실제 Desktop·폐쇄망 전체 통합 검증은 별도 환경 준비 후 수행한다. Windows 신호를 이용한 사용자 Ctrl+C 동작 자체는 자동 UI 검증하지 않았으며 테스트 종료는 자식 프로세스 종료로 확인했다.
