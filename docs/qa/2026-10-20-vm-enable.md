# 현재 PC Windows Sandbox 활성화

2026-10-20 (Asia/Seoul). 사용자가 현재 PC의 VM 환경 구축을 요청하여 기존 준비 단계 다음으로 진행했다. 호스트 앱 UI를 제어하지 않고 Windows의 관리자 승인으로 기존 Enable-WindowsSandbox.ps1을 실행했다.

## 확인 결과

- 프로세스 종료 코드 3010. 결과는 ok=true, state=Enabled, restartNeeded=true, automaticRestart=false다.
- 반입 manifest의 모든 파일 해시를 다시 대조했다. 앱 0.12.0, Desktop Editors 10.0.0, 고정 Node 24.22.0 묶음이 일치한다.
- 호스트 HypervisorPresent=true, 물리 메모리 약 15.7GB. WSB의 메모리 4096MB·네트워크/클립보드 차단을 확인했다.
- 활성화 후 -Check로 재부팅 전제 미충족과 ready=false를 확인했다. VM ID 기록은 없으며 게스트를 시작하지 않았다.
- 이 작업은 환경 활성화 작업이며 앱 코드를 바꾸거나 기존 93개 자동 테스트를 재실행하지 않았다. 배포본 검증은 직전 [재개 QA](2026-10-20-vm-resume.md) 기록을 따른다.

## 재부팅 후 이어가기

자동 재부팅하지 않았다. 사용자가 작업을 저장하고 직접 재부팅하거나 재부팅에 명시적으로 동의한 후에만 진행한다. 원격 Git 기록과 현재 Windows 상태를 혼동하지 않도록 아래 점검부터 다시 수행한다.

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts/vm/Start-WindowsSandbox.ps1 -ConfigFile ../work/vm/windows-sandbox/Workbench-QA.wsb -Check
```

ready=true, 종료 코드 0이면 같은 명령에서 -Check를 빼고 게스트 준비를 실행한다. 이 실행기는 호스트에 Sandbox 화면 연결을 열지 않는다. 결과는 work/vm/windows-sandbox/results에 기록된다. 실제 게스트 첫 부팅·설치·앱 페이지 편집·undo/저장 및 게스트 LLM은 여전히 미검증이다. 네트워크가 차단되어 있고 합성 PPTX·LLM 모델은 이번 반입 묶음에 없다. Sandbox를 종료하면 게스트 상태가 사라진다.
