# Marker 실제 추출·근거성 비교 QA — 0.11.0

## 작업 범위와 환경

2026-10-19에 실험을 수행하고 10-20에 결과·코드를 정리했다. Marker 연동과 로컬 LLM의 할루시네이션 개선 여부를 같은 작업 묶음으로 검증했다. 사용자 PC UI는 제어하지 않았다.

- Python 3.12.14, Marker 2.0.0, Surya 0.22.1, pdfplumber 0.11.9. 전체 설치 버전: scripts/marker/requirements.lock.
- 합성 3페이지 PDF: 본문·승인/제안 예산 표·두 단 배치·이미지 전용 송장. 렌더링한 3페이지를 모두 시각 검수했다.
- Marker fast / OCR 끔 약 25초, OCR 켬 첫 모델 준비 포함 약 122초·캐시 후 약 25초. 표는 구조화됐고 두 단 본문은 합쳐졌다.
- 질문 모델: llama.cpp b8201 + Qwen2.5 1.5B Q4_K_M, CPU 2스레드. Marker OCR은 별도 Surya 로컬 VLM 사용. 외부 LLM 보정(use_llm)은 끔.
- 본시험은 각 22문항 × 두 조건 × 두 실험 = 88응답. 모델/프롬프트/출력 제어 고정, 질문별 조건 실행 순서 교대. 요청/형식 실패 0건.

## 결과

| 실험 | 일반 텍스트 정답 | Marker 정답 | 일반 텍스트 잘못된 단정 | Marker 잘못된 단정 |
| --- | --- | --- | --- | --- |
| OCR 끔 | 13/22 | 14/22 | 8/22 | 8/22 |
| OCR 켬 | 14/22 | 13/22 | 7/22 | 9/22 |

OCR을 켜면 스캔 정답은 0/2 → 2/2다. 하지만 전체 환각 대리 지표는 개선되지 않았다. 원본에 없는 6문항의 거부도 OCR 켠 Marker 조건에서 4/6 → 2/6으로 감소했다. OCR 정답 두 건도 모델이 페이지 인용을 누락했다. **정보 획득 개선과 LLM 답변의 근거성 개선을 구분한다.** 작은 탐색 시험으로 일반적·통계적으로 유의한 개선을 입증하지 못했다.

예비 단답/출처 형식 시험에서는 출력 형식 실패가 많았다. 예비 응답을 숨기지 않고 pilot-format-failure.json에 보존했으며 본시험 통계와 섞지 않았다. JSON schema를 양쪽에 동일 적용한 후 본시험을 수행했다.

## 코드 검증

전체 Node 자동 테스트 78개 통과. 새 검증은 페이지 출처/중복/한도, 사실·근거·거부·인용·형식 실패의 분리, 실제 CLI의 양쪽 고정 설정과 문서 해시 불일치의 네트워크 전 거부를 포함한다. Python 추출은 모의가 아닌 실제 Marker 모델로 두 모드 실행했다.

Windows에서 Surya 종료 신호가 부모 콘솔을 중단하는 문제를 관찰했다. 작업자가 생성한 하위 프로세스만 먼저 종료하도록 보완한 뒤 OCR 추출을 다시 실행하여 종료 코드 0과 결과를 확인했다. upstream이 이미 종료된 PID에 WinError 87 경고를 남기는 것은 남아 있으며 원본/모델 출력 처리에는 영향을 주지 않았다. 사용자 소유의 기존 서버는 종료하지 않는다.

Node·Python·모델이 포함되지 않은 프로젝트 배포물 생성 확인. 실제 PDF 뷰어/패널 UI 연결·실제 Desktop 엔진·사내 LLM·폐쇄망 신규 설치는 이번 검증 범위가 아니다.
