# 로컬 서비스 포트 설정 QA

- 실행일: 2026-10-19 (Asia/Seoul)
- 대상: PoC 0.3.3, plugin/app.js 및 plugin/index.html
- 환경: Windows, Node.js 24.15.0, Node VM의 모의 DOM, 실제 loopback HTTP 서버
- 입력: 합성 문장·합성 연결 코드. 사내 주소·모델·문서 미사용

## 구현

설치형 플러그인의 기본 포트는 4318이다. 로컬 HTTP 화면은 현재 주소의 포트를 기본으로 사용한다. 포트를 입력하여 연결할 수 있으며 목적지는 127.0.0.1로 고정한다. 포트는 1~65535의 정수 표기만 받고 잘못된 입력은 인증정보 전송 전에 거부한다. 포트·연결 코드 변경은 연결 완료 상태를 해제한다. 요청 중 설정을 잠그고 연결 확인 중 중복 요청을 막는다.

## 검증

`node --test test/app.test.mjs`: 4개 통과.

- 설치형 기본값 4318 확인. 빈 값, 0, 65536, 음수, 소수, 지수, 경로·호스트 삽입 입력은 요청 전 거부. 경계 1·65535는 모의 fetch로 URL과 성공 처리를 확인했으며 해당 포트를 실제로 열지는 않았다.
- 임의 포트의 실제 로컬 서비스에 설치형 핸들러로 health 및 propose 요청 성공. 수정안 확인. 포트 변경 후 요청 차단 및 재연결 후 활성화, 연결 코드 변경 후 비활성화 확인.
- localhost·127.0.0.1의 HTTP 주소에서 현재 포트 기본값 및 실제 health 연결 확인. 외부 호스트 주소에서는 해당 포트를 채택하지 않음.
- 연결 요청 진행 중 포트·연결 코드 잠금, 중복 연결 요청 차단, 완료 후 잠금 해제 확인. 취소할 수 없는 health 요청에는 취소 버튼을 표시하지 않음.

`npm test`: 전체 40개 통과, 실패·건너뜀 0개.

`npm run package`: 플러그인, 소스 ZIP, SHA-256 목록 생성 성공.

## 검증 한계

실제 app.js 핸들러를 실행했으나 DOM은 모의 객체다. 브라우저의 렌더링·입력 제약·CORS/PNA 정책 및 실제 Desktop UI의 포트 설정은 이번에 검증하지 않았다. 기존 서버의 file:// 및 null Origin 검사는 별도 자동 테스트로 유지한다. 새 UI의 실제 편집기 동작은 별도 VM/전용 테스트 PC에서 확인한다.
