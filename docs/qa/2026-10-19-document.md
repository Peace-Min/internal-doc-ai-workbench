# 문서 범위 질문·요약 QA

- 실행일: 2026-10-19 (Asia/Seoul)
- 대상: PoC 0.6.0, 문서 읽기·출처·범위 UI
- 환경: Windows, 개발 Node 24.15.0, 배포 Node 24.22.0, 헤드리스 Chromium
- 합성 문서·코드·응답만 사용. 실제 사내 게이트웨이·문서 미사용

## 자동 검증

전체 60개 통과, 실패·건너뜀 0개. 기존 55개에 5개 테스트를 추가했다.

문서 명령 테스트 3개:

1. 여러 슬라이드·문단·run의 순서와 출처, 빈 슬라이드 유지, 제외·빈 개체 집계. 선택 API를 호출하지 않으며 쓰기 0회. 읽기 전용 표식을 제거해도 document scope의 적용 거부.
2. 출처 포함 12,000자 경계 및 초과, 여러 슬라이드 합계 초과, 유효 텍스트 뒤 NUL 발생 시 전체 캡처 오류. 부분 text 없음.
3. 200슬라이드 경계·201슬라이드 거부, 2,001개 개체 거부, 빈 문서·지원하지 않는 개체만 있는 문서 거부.

화면 테스트 2개:

1. 문서 범위의 출처 포함 전송·제외 안내·답변 전용 표시. 편집 복귀 시 선택 범위로 강제하고 기존 대상·결과 무효화.
2. 문서 캡처 실패 시 이전 출처·대상을 지우고 부분 자료 요청을 차단.

기존 두 프로토콜의 loopback HTTP 테스트에서 없는 출처·제외 내용을 분석했다고 주장하지 말라는 프롬프트도 확인했다. 모델이 실제로 준수하는지 검사한 것은 아니다.

## 브라우저 흐름

사용자 창을 띄우지 않는 playwright-cli 세션에서 실제 UI와 모의 편집기를 사용했다.

- 선택 개체가 본문 B인 상태에서도 본문 A/B를 각각 슬라이드 1/2 자료로 읽고 출처 두 개를 표시.
- 화면에서 미리 본 자료와 요청 본문의 일치, 제외 범위 안내, 답변 뒤 원문 불변 및 적용 버튼 없음 확인.
- 범위 전환 시 기존 답변·대상 초기화. 출처를 더하면 상한을 넘는 12,000자 본문은 읽기 단계에서 거부하고 추가 요청 없음.
- 편집 모드로 바꾸면 선택 개체로 복귀하고 문서 범위 선택 비활성화.
- 오류 로그 0개. [합성 화면](assets/document-summary.png)의 표시·배치 확인 후 브라우저와 임시 서비스 종료.

시험용 API 응답을 가로채 두 출처가 포함된 합성 답변을 제공했다. 사내 모델 결과·품질·인용 정확성으로 해석하면 안 된다.

[CLI 재현 함수](assets/document-browser-flow.js)는 mock 데모에서 로컬 연결을 완료한 상태를 전제로 한다. output/playwright 폴더를 준비하고 다음을 실행한다.

```sh
npx --yes --package @playwright/cli playwright-cli -s=document-qa run-code --filename docs/qa/assets/document-browser-flow.js
```

## 근거와 한계

[고정 SDK](../06-desktop-api-research.md)의 GetAllSlides와 GetAllDrawings 존재 및 구현을 확인했다. 이를 실제 Desktop에서 호출한 것은 아니며, 브라우저 데모와 모의 엔진은 실제 API 자료 구조·권한·응답 시간을 대신하지 않는다.

현재 상한은 한 번에 전송할 수 있는 문서 텍스트 범위다. 자동 분할·검색·이미지 OCR·표·그룹·노트·마스터 추출은 미구현이다. 모델의 인용은 지시 조건이며 프로그램으로 검증하지 않는다. 숨긴 내용이 포함된다는 점을 화면과 Wiki에 명시했다.

## 배포

런타임 포함 Windows ZIP을 갱신하고 별도 폴더에 풀었다. 시스템 PATH 없이 실행기 사전 점검과 동봉 Node 24.22.0의 전체 60개 테스트를 통과했다. 실제 폐쇄망 신규 설치나 Desktop QA는 아니다.
