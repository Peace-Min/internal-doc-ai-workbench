# 편집 실패 원문 복구 QA

- 실행일: 2026-10-19 (Asia/Seoul)
- 대상: PoC 0.3.2, plugin/editor-command.js 및 test/editor.test.mjs
- 환경: Windows, Node.js 24.15.0, Node VM의 모의 편집 API
- 입력: ‘원래 문장’, ‘수정 문장’, ‘다른 개체’의 합성 텍스트만 사용

## 문제와 수정

기존 구현은 원문 삭제 후 AddText가 예외를 던지면 바깥 catch로 이동해 복구를 시도하지 않았다. false 반환 시 복구도 성공 여부를 검사하지 않았다.

삭제·삽입의 false 반환과 예외를 함께 처리하고 수정안 결과를 대조한다. 오류 시 원문이 그대로면 추가로 쓰지 않는다. 변경되었으면 삭제 성공을 확인한 뒤 원문을 삽입하고 반환값과 텍스트를 검사한다. 복구 확인 실패는 추가 편집·저장 전 확인과 실행 취소/사본 복구 안내로 전달한다.

## 재현 및 결과

`node --test test/editor.test.mjs`: 9개 통과.

추가 테스트 4개에서 다음 13가지 실패 주입을 검증했다.

- 수정안 삽입: false, 예외, 부분 쓰기 후 예외, 실제 쓰기 없는 true 반환. 모두 원문 복구 확인, 다른 개체 불변, 적용 성공 응답 없음.
- 최초 삭제: 변경 없는 false/예외, 삭제 후 false/예외. 모두 원문 유지 또는 복구, 수정안 삽입 없음.
- 복구 삭제: false/예외. 부분 텍스트에 원문을 덧붙이지 않고 recoveryFailed=true 및 복구 안내 반환.
- 복구 삽입: false/예외/실제 쓰기 없는 true. recoveryFailed=true, 원문 복구 성공을 주장하지 않음.

`npm test`: 전체 36개 통과, 실패·건너뜀 0개.

`npm run package`: 플러그인, 소스 ZIP, SHA-256 목록 생성 성공. 실제 플러그인 메뉴 설치 검증과는 구분한다.

## 한계와 다음 확인

실제 Desktop UI를 제어하지 않았고 실제 사내 연결·문서를 사용하지 않았다. 모의 API의 텍스트 결과만 검증했으며 실제 엔진에서 API 실패가 발생하는지, 명령 종료 후 자동 롤백되는지, undo 및 서식이 보존되는지는 미검증이다. 별도 VM/전용 테스트 PC에서 합성 PPTX로 확인한다.
