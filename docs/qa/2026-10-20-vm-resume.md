# 세션 재개 및 VM 전제 재확인

실행일: 2026-10-20 (Asia/Seoul). 앱 0.12.0, 개발 Node 24.15.0, 배포 Node 24.22.0 Windows x64.

## 기획과 변경

원격 fe36d36까지 fast-forward 동기화했다. Git 기록에는 Sandbox 활성화와 반입 준비가 있었지만 이번 환경에서는 기능 InstallState 2(비활성), wsb.exe 부재, 이전 반입 디렉터리 부재를 확인했다. 현재 프로세스는 관리자 권한이 아니다. 이전 환경 기록을 현재 실행 전제로 사용하지 않았다.

Start-WindowsSandbox.ps1에 읽기 전용 -Check를 추가했다. 설정·필수 입력 파일·Sandbox 기능·CLI·이전 활성화 결과의 재부팅 필요 여부를 구분한다. 일반 실행도 같은 검사 후에만 VM 시작 단계로 간다. 점검 자체는 Windows 기능·설정 파일·VM 상태를 변경하지 않는다. 입력 파일의 존재와 해시 검증은 구분하며 해시는 기존 준비기/게스트가 검사한다.

## 이번 검증

- 최신 원격 상태에서 기존 자동 테스트 92개 통과. 준비 상태 검사 테스트 추가 후 전체 93개 통과, 실패·건너뜀 0개.
- 없는 설정 경로에 -Check를 실행하면 JSON과 종료 코드 1을 반환하며 준비 디렉터리를 만들지 않는다. vmStarted/automaticRestart는 false다.
- 공식 v10.0.0 DesktopEditors_x64.zip을 받아 고정 SHA-256 `54979d04f1cdca56deb0c62e0356355a45f392cdb54f04f6b7e436b1f44c3605`와 일치 확인. 실행하거나 호스트에 설치하지 않았다.
- 고정 Node 실행 파일/고지와 최신 소스로 VM 반입 묶음을 새로 생성했다. 워크스페이스 work에만 두며 Git에 포함하지 않는다. 합성 PPTX는 이번 묶음에 추가하지 않았다.
- 실제 WSB XML 파싱 및 PowerShell 스크립트 3개의 AST 구문 분석 통과. 읽기 전용 입력과 쓰기 가능한 결과 폴더 공유를 확인했다.
- 준비 후 -Check 결과는 configExists/inputFilesPresent true, featureEnabled/cliAvailable/ready false, environmentReadFailed/restartRequired/vmStarted/automaticRestart false였다. restartRequired false는 기능 활성화나 부팅 준비 완료를 뜻하지 않는다. 기존 활성화 결과 파일이 없기 때문이다.
- Node 포함 배포 ZIP을 별도 공백 포함 경로에 풀고 PATH 없이 실행기 사전 점검 및 전체 93개 테스트를 통과했다. PowerShell을 사용하는 테스트도 시스템 절대 경로를 사용하여 PATH에 의존하지 않는다.

## 남은 전제

관리자 권한으로 Enable-WindowsSandbox.ps1을 실행한 뒤 반환된 restartNeeded를 확인해야 한다. 재부팅은 사용자 작업 저장과 명시적 동의 후에만 한다. 이 세션에서는 기능 활성화·권한 상승·재부팅·VM 시작·호스트 Desktop UI 제어를 하지 않았다.

실제 VM 게스트 준비·페이지 편집·undo/redo·저장/재열기·렌더링·사내 연결은 여전히 미검증이다. [재개 절차](../wiki/windows-vm-qa.md)의 -Check부터 다시 실행한다. 과거의 브라우저·로컬 모델·Marker 검증을 이번 세션에서 다시 수행했다고 표기하지 않는다.
