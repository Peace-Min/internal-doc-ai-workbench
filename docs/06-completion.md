# 최종 결과물과 완료 판정

기준은 01-planning.md의 R01~R10과 03-qa.md의 Q01~Q16이다. 구현/모의 검증/실제 엔진 검증/사내 인수를 서로 바꾸어 쓰지 않는다. 사용자 요청에 따라 접근 가능한 작업은 피드백 루프로 진행하되 외부 전제가 없는 것처럼 최종 완료를 선언하지 않는다.

## 독립적으로 진행할 작업

- PPTX 페이지 수정: 실제 플러그인 읽기→검토→적용→한 번 undo/redo→충돌 거부→숫자 보호→저장/재열기와 서식 비교. 인수 절차는 wiki/page-edit-acceptance.md. 현재 실제 열기/캡처만 확인했고 전체 편집 인수는 미완료다.
- 설치/배포: 고정 해시·원본 고지·런타임 포함 배포물, 사용자 계정 설치/플러그인 백업, 인터넷 차단 VM 새 앱 설치 및 API 점검을 0.13.0에서 확인했다. VC++ 런타임은 별도 사전 설치였으며 전체 PC 이미지/사내 인수와 구분한다. 증거는 qa/2026-10-21-offline-install.md.
- PDF: 같은 PC 편집기의 첫 페이지 열람은 확인했고 0.14.0 선택 질문·요약은 실험적 후보로 구현/모의 SDK·브라우저 검증했다. 실제 선택 API/패널, 페이지 전체 분석·Marker 연결, PDF 편집·저장 인수는 미완료다. Marker CLI 추출 실험은 PDF UI 수정 기능의 완료 증거가 아니다.
- 기록/출처/오류 처리: 원문 변경 없이 분석, 출처 대조와 보고서, 실패 시 부분 결과/미검증 답변을 정상 결과로 표시하지 않는지 회귀 검증한다. 기본 테스트/헤드리스 결과는 현재 있고 실제 Desktop 통합은 추가 확인한다.

## 외부 전제와 완료에 필요한 증거

- R01/Q09 클라우디움: 실제 API 규격·테스트 접속·인증·버전/권한/충돌 사례가 필요하다. 가상의 API를 실제 연동으로 만들지 않는다.
- R05 및 사내 인수: 실제 LLM 엔드포인트/모델·인증·TLS/프록시 조건과 합성 문서 요청 성공이 필요하다. OpenAI/Anthropic 어댑터 자동 시험과 로컬 모델은 이 검증을 대체하지 않는다.
- 실제 편집 인수: 호스트 화면을 점유하지 않는 사용 가능한 VM UI가 필요하다. 현재 read-only/UIA 일반 컨트롤 성공과 실제 입력의 no_interactive_desktop 실패를 분리한다. 잠금/보안 화면을 우회하지 않는다.
- 폐쇄망 전체 흐름 Q14: 실제 문서 불러오기→AI→분석→수정→저장, 사내 모델·저장소를 포함한 차단망 인수 증거가 필요하다. 네트워크 차단 VM에서의 mock API만으로 통과시키지 않는다.

## 이번 세션 제한

VM LLM 설치·실행 준비 명령은 자동 승인 검토가 `blocked by policy`로 실행 전에 거부했다. 세부 사유는 제공되지 않았다. 명령을 재포장하거나 다른 경로로 우회하지 않았고 realInferenceTested는 false다. 공식 공개 런타임/모델은 호스트 work/local-llm과 VM 입력에 다운로드·해시 확인하여 준비된 상태다. 설치·기동·추론 성공으로 계산하지 않는다.

## 완료 결과물

검증된 소스 커밋/원격 동기화, Windows 배포 ZIP·플러그인·소스·SHA256SUMS, 설치/실행 Wiki, 실제 인수 증거와 남은 외부 전제 목록을 함께 제공한다. 제품 전체 완료는 위의 미완료·외부 전제가 해소된 뒤 판정한다. 최신 작업과 실제 파일 위치는 HANDOFF.md를 따른다.
